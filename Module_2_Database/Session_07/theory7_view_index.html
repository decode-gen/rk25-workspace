Lý thuyết Tối ưu hóa CSDL: VIEW & INDEX trong MySQL

Nắm vững nguyên lý hoạt động của Bảng ảo (View) và Chỉ mục tìm kiếm (Index) để tối ưu hiệu năng và bảo mật trong hệ quản trị cơ sở dữ liệu.

1. Tổng quan về VIEW (Bảng ảo)

VIEW cho phép tổng hợp kết quả từ một hoặc nhiều bảng tùy theo tiêu chí mong muốn. Bản chất của View là một câu lệnh truy vấn SQL được lưu trữ trên server cơ sở dữ liệu. Khi truy xuất dữ liệu từ View, hệ thống thực thi câu truy vấn này và trả về dữ liệu cập nhật tức thời theo các bảng thành phần.

Cú pháp tạo View: 
CREATE [OR REPLACE] VIEW view_name AS
SELECT column1, column2, ...
FROM table_name
WHERE condition;
Thao tác quản lý View: 
-- Thay đổi View
ALTER VIEW view_name AS SELECT ...;

-- Xóa View
DROP VIEW IF EXISTS view_name;

Lợi ích cốt lõi của VIEW:

  • Đơn giản hóa truy vấn: Giảm thiểu việc phải viết đi viết lại các câu lệnh JOIN phức tạp giữa 4-5 bảng.
  • Bảo mật & Phân quyền: Ẩn các cột dữ liệu nhạy cảm (như mật khẩu, mức lương, số CCCD/CMND) đối với người dùng không có thẩm quyền.
  • Tương thích ngược: Hỗ trợ tái cấu trúc bảng mà không làm hỏng các phần mềm hay ứng dụng cũ đang truy vấn CSDL.

2. Tổng quan về INDEX (Chỉ mục tìm kiếm)

INDEX là một cấu trúc dữ liệu đặc biệt (thường dạng B-Tree) giúp hệ quản trị CSDL nhanh chóng xác định vị trí của bản ghi mà không cần quét tuần tự toàn bộ bảng (Full Table Scan).

Index đơn (Một cột):

Áp dụng cho cột thường xuyên xuất hiện độc lập trong mệnh đề WHERE, JOIN hoặc ORDER BY.

CREATE INDEX idx_department 
ON employees(department);
Index kết hợp (Nhiều cột - Composite Index):

Áp dụng cho các truy vấn lọc đồng thời nhiều điều kiện theo thứ tự ưu tiên từ trái qua phải.

CREATE INDEX idx_status_date 
ON orders(order_status, order_date);

Lưu ý khi tạo và quản trị Index:

  • Ưu điểm: Tăng tốc độ truy vấn SELECT lên gấp hàng chục đến hàng trăm lần đối với bảng dữ liệu lớn.
  • Chi phí đánh đổi: Làm chậm tốc độ các câu lệnh ghi dữ liệu (INSERT, UPDATE, DELETE) vì mỗi lần thay đổi dữ liệu, hệ thống phải cập nhật lại cây chỉ mục.
  • Nguyên tắc vàng: Chỉ tạo Index trên các cột có tần suất tìm kiếm cao, độ chọn lọc lớn (High Cardinality) và không tạo thừa chỉ mục.
