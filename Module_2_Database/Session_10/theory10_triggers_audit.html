Lý thuyết Trigger trong MySQL: Ghi nhật ký & Bảo vệ toàn vẹn dữ liệu

Khám phá toàn diện Trigger: BEFORE / AFTER events, cơ chế đối chiếu OLD / NEW, kỹ thuật ghi Audit Log và dùng SIGNAL SQLSTATE chặn lỗi nghiệp vụ.

1. Tổng quan về Trigger trong MySQL (Audit Log & Business Integrity)

Trigger là đoạn mã SQL tự động kích hoạt (bắn ra) khi xảy ra một trong ba sự kiện: INSERT, UPDATE, DELETE trên bảng. Trigger không thể gọi trực tiếp từ người dùng bằng lệnh CALL.

Trigger AFTER UPDATE (Ghi nhật ký thay đổi): 
DELIMITER //
CREATE TRIGGER trg_salary_change
AFTER UPDATE ON employees
FOR EACH ROW
BEGIN
    IF OLD.salary <> NEW.salary THEN
        INSERT INTO salary_log(emp_id, old_salary, new_salary)
        VALUES (OLD.id, OLD.salary, NEW.salary);
    END IF;
END //
DELIMITER ;
Trigger BEFORE INSERT / DELETE (Chặn vi phạm): 
DELIMITER //
CREATE TRIGGER trg_check_stock
BEFORE INSERT ON cart_items
FOR EACH ROW
BEGIN
    DECLARE v_stock INT;
    SELECT stock INTO v_stock FROM products WHERE id = NEW.prod_id;
    IF NEW.quantity > v_stock THEN
        SIGNAL SQLSTATE '45000'
        SET MESSAGE_TEXT = 'Kho không đủ hàng!';
    END IF;
END //
DELIMITER ;

Bảng tra cứu biến ngữ cảnh OLD và NEW:

  • INSERT: Chỉ có NEW (chứa dữ liệu sắp hoặc vừa được chèn). Không có OLD.
  • UPDATE: Có cả OLD (dữ liệu ban đầu) và NEW (dữ liệu mới cập nhật).
  • DELETE: Chỉ có OLD (dữ liệu của dòng sắp hoặc vừa bị xóa). Không có NEW.
