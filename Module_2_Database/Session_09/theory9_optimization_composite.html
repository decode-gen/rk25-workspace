Lý thuyết Tối ưu hóa CSDL & Nghiệp vụ Kho trong Stored Procedure

Làm chủ các kỹ thuật tối ưu hóa chỉ mục tìm kiếm, thiết kế báo cáo đa chiều qua View và viết thủ tục Stored Procedure kiểm soát giao dịch đặt hàng & tồn kho.

1. Tối ưu hóa truy vấn với Index kết hợp & Phân tích EXPLAIN

Khi dữ liệu bảng đạt đến hàng triệu bản ghi, việc truy vấn tìm kiếm bằng nhiều điều kiện (ví dụ: tìm khách hàng theo email hoặc số điện thoại) bắt buộc phải dựa vào Chỉ mục (Index) để tránh việc đọc toàn bộ đĩa (Full Table Scan).

Chỉ mục duy nhất (UNIQUE INDEX):

Áp dụng cho các cột dữ liệu không bao giờ được phép trùng lặp như Email, CCCD, Mã định danh.

CREATE UNIQUE INDEX idx_cust_email 
ON customers(email);
Đánh giá hiệu năng bằng EXPLAIN:

Lệnh EXPLAIN giúp phân tích xem MySQL có tận dụng được chỉ mục đã tạo hay không.

EXPLAIN SELECT * FROM customers 
WHERE email = 'an@email.com';

2. View tổng hợp & Quản lý tồn kho trong Stored Procedure

Trong các ứng dụng thương mại điện tử thực tế, việc tạo đơn hàng không đơn thuần là câu lệnh INSERT, mà cần phải kiểm tra số lượng tồn kho trong bảng sản phẩm, tính toán thành tiền và trừ kho tự động.

View báo cáo doanh thu đa bảng: 
CREATE VIEW view_customer_spending AS
SELECT c.customer_id, c.customer_name,
       COUNT(o.order_id) AS total_orders,
       COALESCE(SUM(o.total_amount), 0) AS total_spent
FROM customers c
LEFT JOIN orders o ON c.customer_id = o.customer_id
GROUP BY c.customer_id, c.customer_name;
Quy trình Stored Procedure kiểm tra kho: 
SELECT stock INTO v_stock FROM products WHERE id = p_prod_id;
IF v_stock < p_quantity THEN
    SET p_message = 'Không đủ tồn kho!';
ELSE
    UPDATE products SET stock = stock - p_quantity WHERE id = p_prod_id;
    INSERT INTO orders (...) VALUES (...);
    SET p_message = 'Đặt hàng thành công!';
END IF;
